📦 puntueitor — Resumen global

Puntueitor es un motor de:
  ingestión de juegos desde APIs externas
  normalización en un modelo canónico (Game)
  enriquecimiento progresivo
  almacenamiento en librerías
  filtrado, ordenación, scoring y selección final

El flujo conceptual que ya tienes bastante claro es:
    RAW APIs
      ↓
    Resolvers
      ↓
    Mappers
      ↓
    Game
      ↓
    Library / LibraryRepository
      ↓
    Filters / Enrichers / Scoring / Sorting
      ↓
    Selector

📁 enrichers/
Responsabilidad: añadir información adicional a un Game ya existente.

base.py
  Clase base de todos los enrichers
  Define una interfaz tipo:
    enrich(game: Game) -> Game
  Permite encadenar enrichers sin acoplarlos a la fuente de datos
👉 Buen diseño: los enrichers no resuelven, solo enriquecen.

hltb_enricher.py
Enricher concreto que:
  usa datos de HowLongToBeat
  añade duración (main, extra, completionist)
  Se apoya en datos ya resueltos / mapeados

📁 filters/
Responsabilidad: filtrar juegos dentro de una librería o colección.

base.py
Interfaz común de filtros

Algo tipo:
  match(game: Game) -> bool

name.py
  Filtro por nombre
  Usa normalización (normalize_title)
  Matching flexible (contains, similarity…)

genre.py
  Filtra por géneros
  Apoya el modelo de Game.genres

duration.py
  Filtra por duración (HLTB)
  Umbrales: corto / medio / largo, etc.
👉 Filters no modifican, solo aceptan o descartan.

📁 igdb/
Responsabilidad: acceso a IGDB como fuente canónica.

service.py
Cliente de IGDB
Métodos de búsqueda:
  por nombre
  por IDs externos (Steam, etc.)
Devuelve raw dicts, no Game
👉 Muy bien separado de mappers.

📁 index/
Responsabilidad: indexación eficiente de juegos.
library_index.py
Índices internos:
  por título normalizado
  posiblemente por ID
Acelera búsquedas y deduplicación dentro de librerías

👉 Esto ordena elegantemente una library

📁 mappers/
Responsabilidad: transformar datos raw → Game.

igdb_mapper.py
Mapea el dict crudo de IGDB a Game
Normaliza:
  título
  fecha
  géneros
  ratings
Punto crítico de consistencia del modelo

👉 Correcto que sea stateless y puro.

📁 models/
Responsabilidad: núcleo del dominio.

game.py
Modelo central Game
Contiene:
  identidad
  metadatos
  datos enriquecidos
Debe permanecer agnóstico de origen

library.py
Representa una librería lógica de juegos
Contiene:
  lista de Game
  filtros aplicados
  operaciones de consulta

selection_context.py
Contexto usado por selectores:
  preferencias
  pesos
  reglas
Permite decisiones reproducibles

util.py

Funciones auxiliares:
normalización de strings
similarity
Compartido por filtros, index, etc.

📁 pipelines/

Responsabilidad: orquestar flujos completos.
add_igdb_results.py

Pipeline:
  búsqueda en IGDB
  mapping
  inserción en librería

enrich_with_hltb.py

Pipeline de enriquecimiento HLTB

Usa:
  resolver
  mapper
  enricher

👉 Pipelines son casos de uso, no lógica de dominio.

📁 raw/

Responsabilidad: modelos crudos de APIs externas.

howlongtobeat/hltb_entry.py
Representación directa del objeto de HowLongToBeat
Sin lógica
Ideal para serialización / caché

👉 Muy buena separación entre raw y dominio.

📁 repository/
Responsabilidad: persistencia.

library_repository.py
Guarda / carga librerías
Controla versionado de schema
Punto único de IO

👉 Correcto que no viva en models.

📁 resolvers/
Responsabilidad: resolver identidades externas.

base_resolver.py
Interfaz común:
    resolve(...) -> raw | None

steam_resolver.py
Steam API
Obtiene datos por appid

epic_resolver.py, gog_resolver.py
Resolución desde tiendas
Normalizan hacia IGDB indirectamente

hltb_resolver.py
Resuelve entradas HLTB
Produce HLTBEntry

👉 Resolver ≠ Mapper (bien separado).

📁 scoring/
Responsabilidad: calcular puntuaciones.

base.py
Interfaz de scoring
  score(game, context) -> float

weighted_score.py
Implementación concreta
Usa pesos configurables

📁 selector/
Responsabilidad: elegir un juego entre candidatos.

base_selector.py
Interfaz:
  select(games, context) -> Game | None

steam_selector.py
Selector específico para resultados Steam
Criterios inmediatos / heurísticos

hltb_selector.py
Selector basado en duración

score_selector.py
Selector genérico:
  calcula score
devuelve el mejor

👉 Selector = decisión final, no transformación.

📁 services/
Responsabilidad: operaciones de alto nivel.

library_ops.py
Funciones helper:
  añadir juegos
  aplicar filtros
combinar pipelines
“Glue code” consciente

📁 sorting/
Responsabilidad: ordenar listas de juegos.

base.py
Interfaz común de sorters

name.py
Orden alfabético

duration.py
Orden por duración

ratings.py
Orden por rating

mixed_score.py
Orden híbrido (rating + duración + otros)

👉 Sorting ≠ Scoring (muy bien separado).
